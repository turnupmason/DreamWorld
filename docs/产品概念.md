## 一句话概念

**现实中少刷手机、多走路、多学习，虚拟世界里的你和你的家就会变得更好；和朋友一起把小镇建起来。**

这是一款 iOS App，一个现实生活的“镜像世界”。用户少用分心 App 的时间、运动步数和学习成果，会变成虚拟世界里的资源，用来种菜、装修房子、买车、建设社区。朋友住在同一个小镇里，可以互相拜访、送礼、一起盖房子。

定位不是“又一个消耗时间的游戏”，而是“帮你和朋友一起过得更好，同时有点乐趣”。用户下载它带着正面动机，没有负罪感。

## 市场空缺与机会

空缺在于：人们想少刷短视频，但没有一个同样不费力、却让人感觉更好的替代品。

- **短视频占据了碎片时间。** 今年上半年头部手游安装量同比下滑，行业分析认为一个重要原因是注意力流向短视频（PocketGamer.biz）。
- **用户愿意为“少刷手机”付钱。** 屏幕时间管理 App Opal 年收入达到 500 万美元（RevenueCat），年费 99.99 美元（Adapty）。
- **但现有产品只会“拿走”，不会“给予”。** 屏蔽类 App 的差评集中在“几天就找到绕过方法”“用了一周就不管用了”（Unstar）。拿走了短视频，无聊还在，人自然会回去刷。
- **游戏化能把“反人性”的事变轻松。** 散步游戏 Pikmin Bloom 今年上半年收入 3570 万美元，5 月单月创下 870 万美元新高（PocketGamer.biz）；而散步赛道大多数产品月流水不到 10 万美元（36氪）。成功的关键是给用户“心理减负”。

短视频天生给不了三样东西：真实的朋友、成就感和积累、主动参与。本产品在这三点上和它竞争，而不是在内容量和刺激感上硬拼。

## 目标用户

核心用户是每天刷短视频超过一小时、刷完常觉得空虚后悔、自己试过控制但没坚持下来的人。首发市场为美国 App Store。

| 用户类型 | 特征 | 他们从产品得到什么 |
| --- | --- | --- |
| 想戒刷的年轻上班族 | 20–35 岁，通勤和午休离不开抖音、Ins | 一个不靠意志力、有朋友一起的替代品 |
| 想多运动的人 | 有 Apple Watch 或计步习惯，但缺乏动力 | 运动变成虚拟世界的成长，看得见回报 |
| 朋友小圈子 | 室友、同学、同事、家人群 | 一起建小镇的共同话题和互相监督 |
| 喜欢经营装扮的人 | 玩过动物森友会、星露谷、模拟人生 | 设计房子和社区的创作乐趣 |

待确认：是否同时面向家长和青少年。面向未成年人会带来额外的隐私与合规要求，建议第一版只面向成年人。

## 核心循环

放下手机赚资源，拿起手机花资源，和朋友一起把小镇建起来。

（原图「现实中的好习惯是燃料，朋友让循环持续转下去」，4 个环节）

1. **现实好习惯**：少刷短视频 · 走路运动 · 学 30 秒知识卡片 → 离线越久，奖励越多 →
2. **获得资源**：金币、材料、稀有种子，角色活力提升 → 自由装修、种菜、买车 →
3. **建设小镇**：房子、菜园、车和装饰，设计自己的家和社区 → 邀请朋友入住、拜访、送礼 →
4. **朋友互动**：拜访、送礼、一起盖房，完成社区共同目标 → 朋友的鼓励和社区目标让习惯坚持下去 → 回到 1

每次打开只需要一两分钟：收资源、升级一样东西、看看朋友送了什么。朋友的鼓励和全镇的共同目标，是让现实中的好习惯坚持下去的关键，也是和单人屏蔽工具最大的区别。

## 功能分层

功能分为资源来源、个人、社交三层：资源来源决定用户在现实中做什么，个人和社交决定虚拟世界里怎么花。

| 层级 | 功能 | 说明 |
| --- | --- | --- |
| 资源来源 | 少用分心 App | 只计算用户自己选定的分心 App（如抖音、Instagram），少用就获得金币和材料；工作必需的 App 不计入，不看总屏幕时间 |
| 资源来源 | 运动 | 读取 Apple 健康的步数、健身时长，转化为资源和角色活力 |
| 资源来源 | 学习 | 30 秒知识卡片（冷知识、英语表达、历史故事），学完得稀有种子或家具 |
| 个人 | 房子 | 自由设计和装修，可以升级扩建 |
| 个人 | 菜园 | 种菜、收获，作物可以送朋友或装饰 |
| 个人 | 车和收藏 | 买车、收集家具和装饰品，表达个性 |
| 个人 | 虚拟分身 | 角色的活力和能力反映现实习惯（见设计原则），外观由用户自由设计 |
| 社交 | 入住小镇 | 5–10 个朋友共享一条街或一座岛，每人拥有一块地 |
| 社交 | 拜访与送礼 | 去朋友家参观、点赞、留言、送礼物 |
| 社交 | 一起盖房子 | 邀请朋友帮忙建造，完成后双方都有奖励 |
| 社交 | 社区共建 | 全镇合作建设公共设施（图书馆、公园），繁荣度大家共享 |
| 社交 | 习惯动态 | 朋友可见“今天完成了目标”这类结果，可选择是否公开 |

小组件是重要入口：桌面和锁屏显示“小王送了你一辆车”“你的菜熟了”这类有意义的社交动态，在用户解锁手机、准备刷视频的那一刻出现。

## 设计原则

这个 App 要让人用得舒服，而不是用得多。这条原则和产品定位一致，也是和开心农场、抢车位这类“越用越累”的游戏最大的区别。

1. **奖励，不惩罚。** 好习惯带来成长和惊喜；没做到时不扣资源、不让东西坏掉。错过几天回来，小镇在等你，而不是一片狼藉。
2. **角色反映活力，不反映体型。** 运动多，角色精神饱满、干活更快、解锁新动作和装备；很久没动，角色只是犯困、打哈欠，休息一下就恢复。体型和外观由用户自由设计，与数据完全分开，避免身材羞辱和对身材焦虑人群的伤害。
3. **克制推送。** 推送只发真正的社交事件，例如“小李送了你一辆车”；不发“菜熟了快来收”这类催促。离线奖励计时期间完全不打扰。
4. **每日有上限。** 每天能做的建造操作有合理上限，用完后小镇会说“今天的活干完了，去过你的生活吧”。
5. **合作为主，较劲为辅。** 社区繁荣是共同目标，比较只在朋友之间、只比结果。互动以送礼、帮忙、恶作剧为主，不做让人心痛的抢夺。
6. **隐私默认关闭。** 健康和屏幕时间数据默认不公开；公开时可以只分享“完成目标”，不分享具体数字。
7. **包容每个人。** 受伤、生病、怀孕或使用轮椅的用户也能参与：支持 Apple 健康的轮椅推动次数，提供“休息日”选项，冥想和拉伸也算活动。工作离不开手机的人也不吃亏：只算自己选定的分心 App，不算总屏幕时间。

## 竞品对比

现有产品各自只解决一件事，目前没有产品把屏幕时间、运动、学习放进一个朋友共建的世界。

| 产品 | 核心行为 | 社交程度 | 盈利模式 | 我们的差异 |
| --- | --- | --- | --- | --- |
| Pikmin Bloom | 走路种花、收集精灵 | 弱 | 内购，2026 上半年约 3570 万美元 | 不只走路；朋友共建小镇 |
| Opal | 屏蔽 App、限制屏幕时间 | 弱 | 订阅，年费 99.99 美元 | 不只拿走，还给予乐趣和陪伴 |
| Forest | 不碰手机时种树 | 弱 | 一次性付费 + 内购 | 有朋友、有建造、有多种资源来源 |
| Finch | 照顾虚拟宠物来自我照顾 | 弱 | 订阅 | 社交小镇而非单人宠物 |
| 大富翁 GO | 掷骰子、升级地产、和朋友互动 | 强 | 内购，史上最快达到 60 亿美元收入 | 资源来自现实好习惯，不靠付费和运气 |
| 动物森友会 | 经营小岛、装扮、拜访朋友 | 中 | 主机买断 | 手机碎片时间可玩，和现实习惯挂钩 |

最需要研究的两个参照：Pikmin Bloom 证明“健康行为游戏化”能赚钱，大富翁 GO 证明“和朋友互动”能带来极强的传播和留存。

## 技术方案（PDF 原稿，已被 `技术方案.md` 更新）

建议 iOS 优先、Swift 原生开发，因为产品的核心依赖都是 iOS 系统能力：屏幕使用时间、健康数据和小组件。

| 模块 | 建议方案 | 注意事项 |
| --- | --- | --- |
| 界面 | SwiftUI | 原生体验，小组件和 App 共用代码 |
| 小镇画面 | SpriteKit（2D 等距视角） | 若一年内要出安卓或做 3D，改用 Unity，并为系统功能单独写原生插件 |
| 屏幕时间 | Family Controls / Device Activity 接口 | 用户通过系统的 App 选择器自选计入的 App 或类别（我们的 App 看不到具体选了什么）；正式上架需向 Apple 单独申请权限，要尽早提交；出于隐私，只能按“达到某个时长”这类阈值触发，拿不到精确分钟数 |
| 运动数据 | HealthKit（步数、健身时长、轮椅推动次数） | 健康数据不得用于广告或出售给第三方，需要清晰的隐私政策；手动录入的数据应过滤，防止刷步数 |
| 小组件 | WidgetKit，桌面和锁屏 | 显示社交动态和小镇状态，是主要的回流入口 |
| 推送 | Apple 推送通知 | 只发社交事件，遵守设计原则第 3 条 |
| 后端 | Firebase 或 Supabase | 资源和交易由服务器计算，防止作弊；朋友关系、小镇数据存在云端 |
| 邀请 | 链接 + iMessage 分享 | 不依赖任何外部社交平台 |

第一个技术任务：用一到两周做屏幕时间接口的最小测试，确认能拿到哪些数据，再定“放下手机”奖励的具体规则。

## 商业模式

以订阅为主、装饰内购为辅；核心玩法和好习惯奖励永远免费，不卖“跳过好习惯”的捷径。

| 收入来源 | 内容 | 原则 |
| --- | --- | --- |
| 订阅（会员） | 更多房子和土地、高级装饰主题、个性化小组件、更大的小镇人数上限、详细习惯统计 | 参考 Opal 证明的付费意愿；建议同时提供月付和年付 |
| 装饰内购 | 限定家具、车、季节性装扮 | 只卖外观，不卖资源，避免“花钱代替好习惯” |
| 季节活动 | 节日主题的社区共建活动 | 免费参与，限定奖励可单独购买 |

不做广告：广告会打断体验，也和“帮你少刷屏”的定位矛盾。

另外，Apple 对年收入较低的开发者有小企业计划，抽成从 30% 降到 15%，上线前要申请。

## 第一版范围与路线图

第一版只做两种资源来源（放下手机、步数）、两样建造内容（房子、菜园）和最基本的社交（邀请、拜访、送礼）。其余功能按内测数据决定先后。

版本路线图 · 4 个阶段，2 道关口（两道关口决定是否继续投入：先验证需求，再看内测留存）：

| 阶段 | 时长 | 内容 |
| --- | --- | --- |
| 验证 | 1–2 周，不写代码 | 访谈 20 个用户；读竞品差评；测屏幕时间接口 |
| **关口一：需求成立** | | 访谈反应强烈、接口可行 |
| 第一版 + 内测 | 内测 4–6 周 | 放下手机 + 步数；房子、菜园；邀请、拜访、送礼 |
| **关口二：留存达标** | | 次日 ≥ 40% · 7 日 ≥ 15% |
| 正式上架 | | 美国 App Store；订阅会员上线；角色活力系统；健身时长 |
| 持续扩展 | 按数据决定顺序 | 学习卡片、图书馆；买车、社区共建；季节活动 |

任何一道关口没通过，就回到上一阶段修改，而不是继续加功能。第一版的开发时长取决于团队规模，待确定。

## 验证计划

在投入正式开发前，用两步验证最核心的问题：现实好习惯换成虚拟成长，再加上朋友陪伴，能不能让人真的少刷视频、每天愿意回来。

**第一步：用户访谈（1–2 周，不写代码）**

- [ ] 访谈 20 个每天刷短视频超过一小时的人：刷完的感受、试过什么方法、为什么失败、会不会和朋友一起用这个产品
- [ ] 读完 Opal、one sec、Forest、Pikmin Bloom 的全部一到三星评论，整理未被满足的需求
- [ ] 做屏幕时间接口的技术测试，确认能拿到的数据

**第二步：TestFlight 内测（4–6 周）**

- [ ] 做出最小可用版本，邀请 5–10 个朋友小组（共约 50–100 人）试用
- [ ] 每周回访，观察是否真的少刷了短视频

**关键指标与目标**

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 次日留存 | ≥ 40% | 参考头部 iOS 休闲游戏水平 |
| 7 日留存 | ≥ 15% | 低于此说明核心循环不够吸引人 |
| 人均邀请人数 | ≥ 1.5 | 社交传播是否转起来 |
| 3 人以上小镇占比 | ≥ 60% | 大多数人是否和朋友一起玩 |
| 短视频时长变化 | 使用 4 周后下降 | 产品是否兑现了承诺 |

判断规则：留存达标但社交指标不达标，先改邀请和共建机制；留存不达标，先改核心玩法，不要急着加功能。

## 风险与待解决问题

最大的风险是冷启动和数据接口，两者都应在正式开发前验证。

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 冷启动：没朋友在玩 | 社交价值发挥不出来，新用户流失 | 单人也能完整体验；新用户可加入“公共小镇”；邀请链接一键入住 |
| 屏幕时间接口受限 | “放下手机”奖励规则无法精细设计 | 尽早申请权限并做技术测试；规则按阈值设计 |
| App 本身变成新的上瘾源 | 违背定位，口碑受损 | 遵守设计原则：每日上限、克制推送 |
| 刷步数等作弊 | 破坏公平，朋友间比较失去意义 | 过滤手动录入数据；资源由服务器计算 |
| 健康数据隐私 | 审核被拒或用户不信任 | 默认不公开，清晰隐私政策，不用于广告 |
| 功能膨胀 | 开发周期拉长，核心体验被稀释 | 严格按版本路线图推进 |

**待团队确认的问题**

- [ ] 产品正式名称和题材世界观（海边小岛、城市街区、森林小镇……）
- [ ] 团队人数、技能（尤其是美术和服务器）和启动资金
- [ ] 是否要在一年内推出安卓版（影响技术选型）
- [ ] 第一版是否只面向成年人
