## Mason 的偏好

- 一律用中文回复。
- 所有信息都要写进 md 文件，新对话直接读文档就能接着做。
- 每次更新都写更新日志、升版本号、打标签、推送到 GitHub。
- 这是 iPhone 手机游戏，不是电脑版。正式版用 Swift（壳）+ 网页画面。
- 画风：喜欢网页版的 2.5D 等距卡通风格（「之前网页的样子非常好，只需要完善就好」）；不喜欢 Kenney / Quaternius 那种 3D 低多边形（「3d 太丑了」）。
- 想要像《模拟人生》一样细致：房子内饰、车、田地、牲畜都能自己设计。
- 健康数据要用得很细：睡眠、三环、训练、呼吸、心率，以及 Oura、Whoop、Apple Watch 等设备。
- 小人要由玩家操控，干活要走过去做，不要自己乱跑。
- 界面少字多图，新用户要有引导（「打开软件全是文字不行」）。
- 在意用户的心理感受：不想公开健身情况的人不能有压力。
- 要想清楚产品为什么让人每天花时间、卖点和终局，不能最后只剩一个普通农场游戏。
- 房子要能一层层往上盖，每层都能自己设计。
- 要高清、好看：头像、字体、弹窗都要精致；小人走路要转身；家具要摆得合理（走得到、不浮空）。
- 想要一个真实的虚拟世界：大社区、路有长有宽、买地越来越贵、真实天气。
- 对细节很敏感：字体要好看（系统字体不行）、缩小后也要好看（不能变方块、不能一坨像素）、动作要真实（不能横着走、不能穿模、不能悬空、不能瞬移）、要有音乐音效、做坏事要有后果。
- 所有东西要「生动形象」：软的东西要画得软，每个动作要有自己的声音，每个按钮都要有反馈。
- 想要宠物（云养宠物、到时间提醒）、深色模式、正式的登录，以及一个全世界用户都在的「世界」。
- 家的画面要「只显示这个家，大而细」，不要小岛、不要别的东西；小镇是朋友家人，世界是所有人；要能看到别人在线走路；奖杯和专属的东西要让别人一看就知道这个人厉害。

## 留下的教训

- 家不能是悬空的一块板 → v0.3.0 起家就在小镇里，周围有邻居、马路、树林、湖。
- 商店分类不能放横向滚动条（「车」「房子」被挤出屏幕没人发现）→ 现在是 3 × 3 九宫格，一眼全看到。
- 按手机尺寸设计，要考虑安全区；测试一律用浏览器手机尺寸（375 × 812）。
- 一键收获不能瞬间完成 → 现在小人一样样走过去收，可以随时停下。
- 3D 低多边形素材不是 Mason 要的风格，不要再提。
- 开屏、说明不能是一屏文字 → v0.4.0 起开屏浮在真实小镇上，每屏一句话，进游戏后手指引导。
- 奖励不能只奖励「能跑的人」 → v0.4.0 起按自己的目标算，有上限；分享默认全关。
- 浏览器面板被隐藏时截图会慢一拍（页面不重画）：先 `Scene.bench(n)`，等一秒再截图。
- 动画比截图快：要检查上楼、躺下这种动作，用 JS 每隔 0.1 秒把画布截成图片排成一排再看。
- 测缩放别用 `Scene.look()`（它不受缩放限制），要模拟滚轮。
- 测试时临时改 `Math.random` 一定要还原，不然整个页面的随机都坏了（刷新页面恢复）。
- 浏览器面板有时会把动画降到每秒 1 帧、截图慢好几秒：用 `Scene.bench(n)` 推进，再把画布截成图片（`toDataURL`）放大看。
- 改了家具画法要连商店缩略图一起测（缩略图里家具没有 it.x / it.y）。
- 用 bash 的 heredoc 写很长的 Python 补丁时可能报「unexpected EOF」：把补丁写成文件再用脚本替换。
