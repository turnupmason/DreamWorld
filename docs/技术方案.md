# 镜像小镇 · 原生 App 技术方案

正式版是 iPhone App，用 **Swift** 开发。**画风沿用网页版的 2.5D 等距卡通风格**，在它的基础上完善。

> 历史：2026-11-06 先推荐过 Unity + 3D 素材，并真的装了 Unity 做了一个试玩版（截图和工程存档在 Windows 电脑的 `D:\Unity\archive\mirror-town-unity-test`）。Mason 看了觉得 3D 太丑，决定不用 Unity，用 Swift，保留网页版的样子（见 `决策记录.md` D18、D19）。

## 做法：A. Swift 原生壳 + 网页画面（Mason 2026-11-06 选定）

- **游戏本体**是 `prototype/`（HTML + Canvas + JS）：画面、玩法、界面全在这里。iPhone App 把整个文件夹打包进去，在全屏 WKWebView 里运行。
- **Swift 外壳**（`ios/`）只做网页做不到的：读 Apple 健康，以后还有屏幕使用时间、小组件、通知、手表 App、内购。
- 两边通过 JS 桥通信（字段见 `ios/README.md`）：网页发 `ready` / `refresh`，Swift 调 `window.onNativeHealth(json)` 和 `window.onNativeWorkout(json)`。
- 好处：画面和网页版一模一样；这台 Windows 电脑能直接测试画面和玩法（浏览器手机尺寸）；Swift 部分小（约 300 行），Mason 在 Mac 上编译。
- 性能：手机尺寸下小镇一帧约 3–6 毫秒。
- 以后玩法定型、需要更高性能时，可以再把画面换成 SpriteKit（原来的做法 B），游戏规则可以照搬。

### iOS 工程（`ios/`）

| 文件 | 作用 |
| --- | --- |
| `MirrorTown.xcodeproj` | 手写的 Xcode 工程。iOS 16+，只支持竖屏 iPhone，Bundle ID `com.mirrortown.app`，自动签名（Team 由 Mason 选），Info.plist 由构建设置生成（含健康权限说明） |
| `MirrorTownApp.swift` | SwiftUI 入口，全屏 `GameView` |
| `GameView.swift` | WKWebView：加载打包进去的 `prototype/index.html`，关掉滚动和回弹，安全区交给网页处理；收到 `ready` 后请求健康授权、每分钟和回前台时推数据 |
| `HealthBridge.swift` | HealthKit 读取：今天的步数、轮椅推动、活动能量、锻炼分钟、站立小时（活动摘要）、正念分钟、体能训练；最近的静息心率、HRV、呼吸频率；昨晚睡眠（各阶段分钟，取记录最多的来源，排除手动输入）；iOS 17 训练镜像监听 |
| `MirrorTown.entitlements` | HealthKit 权限 |
| `Assets.xcassets` | App 图标（1024 占位图，由脚本生成） |

`prototype/` 在工程里是文件夹引用（路径 `../prototype`），打包时整个复制进 App。

## 整体结构

```
iPhone App（Swift）
├── 游戏画面：家园、室内、街道、小人操控、商店、仓库、排行、邮箱
│   └── 网页画面引擎（WKWebView 里运行 prototype/）
├── Swift 原生功能
│   ├── HealthKit：步数、三环、体能训练、睡眠阶段、心率、HRV、呼吸、正念、轮椅推动
│   ├── Family Controls / DeviceActivity：分心 App 用了多久（带一个扩展程序）
│   ├── WidgetKit：锁屏和桌面小组件
│   ├── ActivityKit：实时活动 / 灵动岛（运动中显示小人）
│   └── WatchConnectivity：和手表 App 通信
├── Apple Watch App（Swift）：开启运动，实时把运动类型、时长、心率镜像到手机
└── 后端（Supabase 或 Firebase）
    ├── 账号、好友、街道、每家的家园状态
    ├── 信件、偷菜记录、礼物、排行
    └── Oura / Whoop 授权中转（他们的 API 需要服务器保存授权）
```

原则：**原始健康数据只留在手机上**，在手机上算出奖励和精力，服务器只存游戏结果（金币、家园、排行）。

## 健康数据接入

| 数据 | 来源 | 游戏里的用处 |
| --- | --- | --- |
| 步数、轮椅推动次数 | HealthKit | 每 1,000 步发奖励、步数目标 |
| 活动能量、锻炼分钟、站立小时 | HealthKit | 活动三环奖励 |
| 体能训练（类型、时长、热量） | HealthKit | 训练奖励；运动结束后小人做对应动作 |
| 睡眠阶段（深睡、REM、核心、清醒） | HealthKit | 自己算睡眠分 → 精力 |
| 心率、静息心率、HRV、呼吸频率 | HealthKit | 「身体状态」卡片；以后可以微调精力 |
| 正念 / 呼吸练习 | HealthKit | 奖励、精力 +1 |
| Oura 准备度、睡眠分 | Oura 官方 API | 优先作为精力分 |
| Whoop 恢复度、劳累度 | Whoop 官方 API | 恢复度优先作为精力分，劳累度可以算进运动奖励 |
| 运动中实时心率和时长 | 自己的 Apple Watch App | 迷你的你：小人同步运动 |
| 分心 App 使用时长 | DeviceActivity | 少刷奖励 |

- Oura 和 Whoop 的睡眠、心率、训练会自动写进 Apple 健康，所以先接 HealthKit 就能覆盖大部分用户；它们独有的准备度 / 恢复度分数，再通过官方 API 接。
- 苹果新出的睡眠分如果开放读取就直接用，否则用睡眠阶段自己算（算法见《游戏设计》）。
- 用苹果自带的「体能训练」App 运动时，其他 App 拿不到实时数据，所以「迷你的你」需要我们自己的手表 App。

## 画风

- 沿用网页版：等距 2.5D、暖色、圆润的卡通风格，像一个小小的模型世界。Mason 认可这个样子（2026-11-06）。
- 在这个基础上完善细节：更多作物、动物、家具、房子、车的造型，更丰富的周边环境（邻居、街道、树林），动作更细（走过去、蹲下、坐、运动）。
- 试过的 3D 低多边形素材（Kenney、Quaternius）效果不满意，不再使用。

## App Store 注意事项

- 健康数据不能用于广告、不能卖给第三方，要有隐私政策，权限说明要写清楚为什么要读。
- 健康数据不能存进 iCloud。
- 屏幕使用时间（Family Controls）的分发权限需要单独向 Apple 申请，审批要时间，要早点申请。
- 需要苹果开发者账号（每年 $99）才能用 HealthKit、TestFlight 内测和上架。
