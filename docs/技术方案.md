# 镜像小镇 · 原生 App 技术方案（草案）

正式版是 iPhone App（之后可能出安卓），画面用真正的 2.5D / 3D 美术素材，不用代码现画。网页原型（`prototype/`）保留作玩法原型和用户访谈，不再继续加画面内容。

## 结论：推荐 Unity + Swift 原生模块

- 游戏本体用 **Unity 6**：3D 引擎，平时用俯视角正交相机，看起来就是 2.5D；进屋、拍照、特写时切成透视 3D。
- Apple 专属功能用 **Swift** 写原生模块，接进 Unity 导出的 Xcode 工程：健康数据、屏幕使用时间、小组件、实时活动、Apple Watch App。

## 方案对比

| | Unity + Swift 模块（推荐） | 纯 Swift + RealityKit | SpriteKit + 预渲染 2.5D 图 | Godot |
| --- | --- | --- | --- | --- |
| 画面 | 3D，正交相机就是 2.5D | 3D | 只能 2.5D，相机不能转 | 3D |
| 做游戏的工具 | 最成熟：编辑器、动画、光照、粒子 | 弱，很多要自己写 | 2D 成熟，但每个角度的图都要提前渲染 | 中等 |
| 现成 3D 素材 | 最多（免费和付费都有） | 要转成 USDZ 格式 | 要自己从 3D 渲染成图片 | 能用，但更少 |
| 健康、屏幕时间、小组件、手表 | 要写 Swift 插件，多一层 | 最顺 | 最顺 | 要写插件，资料少 |
| 以后出安卓 | 基本不用重写 | 要重写 | 要重写 | 基本不用重写 |
| 我在这台 Windows 电脑上能不能编译、试玩 | 能，可以自己看截图检查 | 不能，每次都要你在 Mac 上跑 | 不能 | 能 |
| 打包上架 | Unity 导出 Xcode 工程，在 Mac 上打包 | Mac 上 Xcode | Mac 上 Xcode | 导出 Xcode 工程 |

没选 SceneKit：Apple 已经主推 RealityKit，SceneKit 不再加新功能，新项目不建议用。

## 整体结构

```
iPhone App
├── Unity 游戏层：家园、室内、街道、小人操控、商店、仓库、排行、邮箱
├── Swift 原生模块（Unity 插件）
│   ├── HealthKit：步数、三环、体能训练、睡眠阶段、心率、HRV、呼吸、正念、轮椅推动
│   ├── Family Controls / DeviceActivity：分心 App 用了多久（带一个扩展程序）
│   ├── WidgetKit：锁屏和桌面小组件
│   ├── ActivityKit：实时活动 / 灵动岛（运动中显示小人）
│   └── WatchConnectivity：和手表 App 通信
├── Apple Watch App（Swift）：开启运动，实时把运动类型、时长、心率镜像到手机
└── 后端（Supabase 或 Firebase）
    ├── 账号、好友、街道、每家的家园状态
    ├── 信件、偷菜记录、礼物、排行
    └── Oura / Whoop 授权中转（他们的 API 需要服务器保存授权）
```

原则：**原始健康数据只留在手机上**，在手机上算出奖励和精力，服务器只存游戏结果（金币、家园、排行）。

## 健康数据接入

| 数据 | 来源 | 游戏里的用处 |
| --- | --- | --- |
| 步数、轮椅推动次数 | HealthKit | 每 1,000 步发奖励、步数目标 |
| 活动能量、锻炼分钟、站立小时 | HealthKit | 活动三环奖励 |
| 体能训练（类型、时长、热量） | HealthKit | 训练奖励；运动结束后小人做对应动作 |
| 睡眠阶段（深睡、REM、核心、清醒） | HealthKit | 自己算睡眠分 → 精力 |
| 心率、静息心率、HRV、呼吸频率 | HealthKit | 「身体状态」卡片；以后可以微调精力 |
| 正念 / 呼吸练习 | HealthKit | 奖励、精力 +1 |
| Oura 准备度、睡眠分 | Oura 官方 API | 优先作为精力分 |
| Whoop 恢复度、劳累度 | Whoop 官方 API | 恢复度优先作为精力分，劳累度可以算进运动奖励 |
| 运动中实时心率和时长 | 自己的 Apple Watch App | 迷你的你：小人同步运动 |
| 分心 App 使用时长 | DeviceActivity | 少刷奖励 |

- Oura 和 Whoop 的睡眠、心率、训练会自动写进 Apple 健康，所以先接 HealthKit 就能覆盖大部分用户；它们独有的准备度 / 恢复度分数，再通过官方 API 接。
- 苹果新出的睡眠分如果开放读取就直接用，否则用睡眠阶段自己算（算法见《游戏设计》）。
- 用苹果自带的「体能训练」App 运动时，其他 App 拿不到实时数据，所以「迷你的你」需要我们自己的手表 App。

## 美术

- 风格：低多边形、暖色调的卡通 3D，整体温馨，像一个小小的模型世界。
- 原型阶段：先用免费可商用（CC0 授权）的 Kenney、Quaternius 模型，里面有带动画的人物、农场动物、家具、车辆、植物，可以很快搭出能玩的版本。
- 正式版：买统一风格的商业素材包（比如 Synty 的 POLYGON 农场、小镇系列），主角、房子和品牌相关的东西找美术定制。所有素材用同一套调色板和材质，保证风格统一。
- 人物动画用通用人形骨骼，一套动画所有人通用：走、跑、蹲下干活、坐、躺、骑车、游泳、瑜伽、举铁、开合跳、挥手、推轮椅、蹑手蹑脚。
- 生长阶段：每种作物 5 个模型，每种动物 3 个（幼崽、半大、成年），果树 3 个。

## App Store 注意事项

- 健康数据不能用于广告、不能卖给第三方，要有隐私政策，权限说明要写清楚为什么要读。
- 健康数据不能存进 iCloud。
- 屏幕使用时间（Family Controls）的分发权限需要单独向 Apple 申请，审批要时间，要早点申请。
- 需要苹果开发者账号（每年 $99）才能用 HealthKit、TestFlight 内测和上架。

## 开发顺序

1. Unity 工程 + 一块家园 + 小人点哪走哪、蹲下种菜收菜 + 几种作物和动物 + 本地存档。
2. 接 HealthKit：步数、三环、睡眠 → 精力、表情和奖励倍率；商店；室内家具。
3. 后端：好友街道、拜访、偷菜偷蛋、写信、排行、全镇等级。
4. Apple Watch App（迷你的你）、实时活动、小组件。
5. 屏幕使用时间、Oura / Whoop、TestFlight 内测。

## 选定 Unity 后需要准备的

- Mac：安装 Unity Hub、Unity 6（带 iOS Build Support）和 Xcode，用来打包装到 iPhone。

- 苹果开发者账号。
